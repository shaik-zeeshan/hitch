Composer — Option 4: Button Morph

The quietest option. The action split button becomes the composer: its rectangle extends straight down into an anchored overlay card that floats over the dimmed file list — no backdrop, Esc dismisses, zero layout shift. The button row stays put as the card's header, and its label morphs with the state (Commit ▾ → Commit ⏎ → Commit on ready… → Create draft PR ⏎ → pushing ↑3…).

Below the header sits the thinnest possible content: a subject that reads like an input only on hover/focus, a borderless auto-growing body, and one muted footer line carrying the scope and the esc hint. The generating affordance is a single 1px iris hairline along the card's top edge; an error swaps it for the oxide attention color plus one error line. PR progress lives entirely in the morphing button label with the hairline running. Exact app tokens, rectangles only — the card almost reads as part of the rail.

Auto mode never opens the body. The auto-commit-push toggle runs an autonomous chain — stage → draft → commit → push — as a single daemon-owned composite Job. Progress shows by the action button morphing its label in place (◌ staging 4 files… → ◌ drafting message… → ◌ pushing ↑1…), the file list staying fully visible and undimmed since nothing overlays it. The chain survives navigating away: a returning GUI re-attaches and restores the button mid-chain from the worktree's active Jobs — indistinguishable from never having left. On completion the label settles to a calm ✓ committed and the app's real bottom-right toast carries the commit info (subject · short sha · pushed). A failed step puts the button in the oxide error treatment with one muted reason line; nothing is committed beyond what already succeeded.
